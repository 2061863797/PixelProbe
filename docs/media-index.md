# 媒体索引

长视频的很多问题（哪里发生了变化、哪些帧是黑帧或白帧）其实只需要每帧的几个统计数。
媒体索引把这些数据**一次解码、存到本机**，之后的查询直接查表。

```bash
pixelprobe index build video.mp4        # 建立索引（顺序解码一遍）
pixelprobe index show video.mp4         # 查看索引；--segments 列出全部分段
pixelprobe changes video.mp4            # 整帧、逐帧的变化检测会自动使用索引
pixelprobe changes video.mp4 --no-index # 强制直接解码
pixelprobe index remove video.mp4       # 删除这个视频的索引
pixelprobe index prune --older-than-days 30          # 预览将清理的旧索引
pixelprobe index prune --older-than-days 30 --apply  # 真正删除
```

## 内容

| 层 | 内容 |
|---|---|
| L0 | 尺寸、帧率、帧数、时长、编码等元数据 |
| L1 | 每帧体检表：通道均值、亮度均值、最小值、最大值、标准差、与上一帧的差异、清晰度（相对值）、画面指纹、块效应（8 像素块边界相对强度，2.0 起；索引格式升为 v2，旧索引自动视为未建立） |
| L2 | 分段：按逐帧差异切成"变化"段与"平稳"段，首尾相接覆盖全片 |
| L3 | 缩略立方体：每帧缩到长边 64 像素；默认总量不超过 128 MB，超出时按固定间隔隔帧保留 |

与上一帧的差异、最小值、最大值和标准差在原始分辨率上计算，表达式与 `changes`、`scan`
完全相同。清晰度和画面指纹在缩小后的图上计算，只用于相对比较和相似帧检索。

## 什么时候会用索引

只有在结果能与直接解码**逐值相同**时才使用，否则自动退回解码：

- `changes`：整帧模式（不写点或区域）、逐帧采样（不写 `step=`，或 `step=1`）；
- `scan`：实际采样间隔为 1 时（较短的视频）；长视频自动隔帧采样，仍走解码；
- MCP 的变化检测和 standard 概览遵循同样的条件。

输出中的 `computed_from` 字段标明结果来自 `index` 还是 `decode`。

## 存放与失效

- 位置：`--index-dir` 指定的目录，否则读环境变量 `PIXELPROBE_INDEX_DIR`，
  再否则为本机数据目录（Windows 为 `%LOCALAPPDATA%\PixelProbe\index`）。
- 每份索引以视频的快速指纹命名。视频被修改（大小、修改时间或首尾内容变化）后，
  旧索引不再匹配，查询会自动改为直接解码。
- 快速指纹不读取整个文件：若文件中间被改写而大小、修改时间和首尾 1 MiB 都不变，
  它无法察觉。索引只是加速数据，正式结果包仍以完整 SHA-256 记录媒体身份。
- 索引写入先进入临时目录，完整写完后才原子提交；删除和清理会先确认没有正在读取的进程。
