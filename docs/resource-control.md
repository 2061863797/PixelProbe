# 资源控制与成本报告

## 执行预算

MCP 主进程只负责调度和协议。媒体头解析、执行计划估算、解码及分析均在
受时限和内存监控的工作进程中运行，能力查询、任务查询和取消不占媒体槽位。

工作进程常驻复用（2.0 起）：任务正常结束（无论成功或已报告的失败）后进程回到空闲池，
下一次调用免去启动和加载依赖的开销，并优先复用刚处理过同一媒体的进程；进程内的
媒体会话会保留已加载的索引。每个任务的内存上限、临时目录、超时和协作取消与以前相同。
以下情况该进程**一律回收、不再复用**：超时、取消、实际内存超限、内存监控失败、崩溃或
通信异常。此外，单个进程累计执行 200 个任务、任务结束后常驻内存超过总内存预算的一半、
空闲超过 300 秒、或空闲进程已达到 `PIXELPROBE_MCP_WORKERS` 个时，也会退出。
本机实测（测试视频，连续 10 次读取请求）：总耗时由 5.37 秒降到 0.81 秒，
首次之后的单次请求由约 0.51 秒降到约 0.016 秒。

任务先按操作上限预留资源。子进程仅读取图片头或视频容器信息，再根据实际
尺寸、选择范围、表示类型、预览和算子计算执行预算；调度器只允许该阶段缩减
已预留预算，不允许未获批准的增长。缩减后唤醒 FIFO 等待任务。
总预算较小时，使用不超过总预算的启动额度，再由子进程判断该请求是否能运行。

- 内存估算包含完整源帧、原生高位深样本、颜色转换、数组副本、浮点中间结果、
  预览和 Python/原生依赖运行开销。裁剪只减少输出载荷，不能绕过完整解码成本。
- 明确的帧区间按末端展示帧计算顺序解码成本，并只保存采样帧。
  稀疏选择也校验未被采样保留的原始区间末端。
- 时间区间保守完整扫描，使用实际 PTS；不按平均帧率伪造映射。
  容器帧数只是估算时明确标记，完整扫描不提供虚假的精确帧数上界。
- 图片信息读取仅解析头部，在完整解码前检查内存。

计划中的固定尺寸字节数按实际形状计算；原生库工作区、压缩结果和未知帧数
采用保守估算与运行期复核。因此计划是可解释的准入估算，不承诺与实测峰值完全相同。
部分工具会预扫描或多次扫描，报告会区分单个共享存储扫描与每遍成本。

## 内存与超限处理

父进程使用 psutil，每 20 毫秒采样工作进程 RSS；Windows 同时检查系统记录的
峰值工作集。RSS 包含解释器、原生库和已驻留的映射文件页。超限返回
MCP_RESOURCE_LIMIT，先发送协作取消，2 秒后仍未退出则终止并确认回收。
只有回收完成后才释放调度预算。内存监控失败会明确终止任务，不静默放行。

预算检查也位于完整图片解码、帧缓存、数组复制、PNG 预览、Zarr 分块写入之前。
逐帧解码、哈希校验和数组分块均有协作检查点。

这不是操作系统级瞬时内存硬限制：两次采样之间可能出现峰值；Linux/macOS
当前按采样 RSS 判断，Windows 可额外发现系统记录的峰值。Python API/CLI
在调用进程内使用协作检查和分配预检；独立进程的强制回收适用于 MCP。
程序不承诺限制外部程序、同一机器的其他服务或任意第三方自定义代码。

## 共享文件预算

同一次执行共用一个线程安全账本，覆盖：

- 完整帧、原生图片副本、NPY 文件头及采样输出；
- 恢复 partial、缓存数组、缓存元数据和所有权标记；
- checkpoint 原文件与原子替换临时文件同时存在时的峰值；
- Bundle 数据、索引、validity、PNG 预览、元数据、日志及 manifest；
- Zarr 元数据及每个实际编码后的 chunk，写入前按准确字节数检查；
- 父进程的请求、状态、结果索引与返回图片：每任务预留 4 MiB，
  计入 MCP 调度的空间预算，工作进程不能使用这部分额度。

预留包含尚未刷盘的字节。同一磁盘上其他未落盘预留也参与空闲空间检查。
重命名迁移记账，实际移除后才释放额度；恢复文件计入总占用，但不再次要求
已占用的空闲空间。缓存因取消、配额或时限中断时不会被误判为损坏。

磁盘不足、ENOSPC 或文件系统配额耗尽会使任务失败。临时结果不作为成功任务领取，
完整 Bundle 保持原子提交及完整性校验。中断后可保留合法 checkpoint 供显式恢复。
每个任务另有父进程管理的临时目录，在任务结束（或进程被回收）后清理。

空间额度表示本次执行的文件峰值，不是整个 Artifact 目录的永久容量限制。
已有正式 Bundle 不自动删除；历史任务及缓存继续使用带归属和活动引用保护的
[维护接口](cache-maintenance.md)。文件系统块开销、外部进程抢占空间和强制结束
期间的系统行为仍由磁盘错误处理兜底；这不是操作系统磁盘配额或安全沙箱。

## 配置与查询

默认总内存为 512 MiB，总临时空间为 4 GiB，最多两个工作进程。
可通过环境变量修改：

| 环境变量 | 单位 / 含义 |
| --- | --- |
| PIXELPROBE_MCP_TOTAL_MEMORY_BYTES | 所有活动媒体工作进程的合计预留字节数 |
| PIXELPROBE_MCP_TOTAL_TEMPORARY_BYTES | 所有活动任务的合计执行文件预算 |
| PIXELPROBE_MCP_WORKERS | 媒体工作进程并行数 |

提高总预算不会取消各工具原有的帧数、载荷或算法上限。
pixelprobe_get_capabilities 返回当前总预算、监控方式和工具上限；
pixelprobe doctor --json 额外检查 psutil 是否可用。

pixelprobe_get_job 增加两个兼容字段：

- resource_plan：完整尺寸、选中帧估计、扫描范围、预扫描说明、内存及空间准入预算；
- resource_usage：工作进程观测内存峰值、受管文件峰值及保留字节数，
  Bundle 完整校验次数与已校验文件字节数。

排队中、预检未完成或进程突然退出时，相应统计可能尚未产生。
文件峰值统计包括受管输出，不包括源媒体与整个历史 Artifact 目录。
正式 Bundle 仍执行提交前和提交后的完整校验；记录重复成本，不以未经验证的
缓存命中替代完整性检查。

## 验证范围

资源专项覆盖真实文件写入、NPY/Zarr、缓存、原子 checkpoint、内存超限后的
真实 spawn 回收和后续请求、失败结果不可领取、多工作进程、VFR 局部范围及
16 位原生样本、真实 2001 帧视频的局部前缀解码、真实重复 PTS 视频的顺序帧身份。
磁盘写满使用确定性的 ENOSPC 故障注入，不填满用户磁盘。
同时保留现有取消竞争、重启及完整结果校验回归。

Windows 本地测试结果记录在 [优化实施检查点](optimization-progress.md)。
Linux 保留正式 Python 测试矩阵；macOS 的 Python/uvx 真实运行仍需在对应平台验证。
开发者本地冻结程序只验证该机器生成的私有产物，不属于正式发行门槛。
